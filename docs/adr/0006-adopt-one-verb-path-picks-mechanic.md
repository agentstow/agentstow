# adopt is one verb; the path picks the mechanic

v1's `adopt` handled one case: a real file/dir in a target moves into the Commons and leaves a link behind (GNU Stow's `--adopt`). Registering a skill whose real home is a git repo — the self-authored-skills workflow — had no command at all: the sanctioned move was a hand-made symlink plus `sync`. v2 keeps one verb and makes where the path lives pick the mechanic, because the user-level intent ("take this under management") is identical in every case and the path determines the direction unambiguously. A rename to `add` and a separate `link`/`add` verb were both considered and rejected: the glossary defines Adopt as the act, and one verb whose report states the mechanic beats two verbs whose difference is the caller's job to know.

Dispatch, in order, on the existing lexically-normalized path:

1. **Commons guard.** A path inside the Commons refuses — "already in the Commons — nothing to adopt." This precedes the git walk-up because the Commons is meant to be committed: with `~/.agents/.git` present, every entry would otherwise classify as repo-backed and the collision matrix would replace the entry with a link to itself, destroying it. The guard is pinned by a test on exactly the committed-Commons scenario.
2. **Absorb** — parent is a Target fan-out dir or a per-agent instructions path: move in, leave a relative link behind. A symlink there refuses; it is already ours or Foreign. Custom targets keep surface precedence even when their dir sits inside a git repo — declaring a custom target is an explicit statement that the dir has fan-out semantics, and a config entry silently changing which mechanic runs would be worse than the hazard it avoids (the custom-target docs carry the warning; `--dry-run` names the mechanic before anything moves).
3. **Source** — a `.git` (directory or file, covering worktrees and submodules) found walking up means the content has a durable home. The Commons gains an **absolute** symlink to the path *as given* — symlink inputs are legal and never resolved through; resolution here is lexical like everything in `link.rs`. The result is a Sourced entry: the repo keeps the truth, edits there reach every agent through the Commons.
4. **Copy** — everything else has no durable home worth pointing at. Content is copied in; the original is untouched, nothing points back, and the message says so: the original is no longer consulted and will diverge. This is a deliberate divorce, not a managed relationship.

External paths take their family from the parent directory's basename (`skills`, `commands`, `agents`); any other parent refuses, naming the accepted ones. No content validation ever — sync does not inspect entries and neither does adopt.

One collision matrix serves all mechanics, compared by resolved targets and real contents: an identical Commons copy → absorb relinks, source replaces the copy with the link, copy no-ops; a divergent copy → refusal ("this is a Variant — merge it by hand"), with no `--force`, because silently discarding one side of a divergence is the failure this tool is defined against; an existing link resolving to the same place → clean no-op, so re-runs are idempotent; a link elsewhere → refusal naming the fix ("remove the Commons link first if you mean to repoint it").

Every mechanic ends by fanning the entry out to every installed agent through sync's own per-entry path — Variants kept, Native agents skipped — so `sync` immediately after any adopt has nothing to say. (agentsync's `import` seeds its state so the next apply is clean — the same property, reached statelessly.) `--dry-run` is the only flag: read-only, lockless, same classification, every action printed in "would" tense. All refusals precede the lock.

## Consequences

- **Sourced entries live and die with their Source.** A missing Source keeps v1 behavior: warned on stderr, skipped from the scan, agent links pruned by the next sync; sync never creates links for a skipped entry. Accepted deliberately — on a machine where the repo is not yet cloned, the skill is honestly absent. `doctor` lists every Sourced entry with its source path and `(source missing)` markers, answering the machine-bootstrap question "what must I clone?"
- **Absorbed and copied entries are indistinguishable afterward** — ordinary Commons entries. Only Sourced entries are recognizable on disk (they are symlinks), exactly what a stateless design permits.
- **The word "source" is an ecosystem homonym and the glossary says so**: chezmoi, agentsync, and dotagents use it for the *canonical* side; here the Source is the outside home an entry points to. The term survives because in agentstow's grammar it is always relational ("Sourced from `<path>`") and, after the Commons rename, nothing else competes for it.
- **Copy accepts future divergence** and pays for it with one loud sentence at adoption time, rather than with a backlink into a directory (a download folder, a scratch dir) that promises no durability.
- **Windows link typing is safe by construction**: every link this verb creates points at a path that exists at creation time, so the file-vs-directory flavour is always read correctly.
- ADR-0002's `mcp adopt` is untouched; MCP entries live inside shared rendered files and keep their own adoption path. The absence of `mcp add` also stands.
- GNU Stow's manual frames `--adopt` as a VCS-review workflow — adopt, `git diff`, keep or revert. The adopt docs borrow that framing for the absorb mechanic: in a git-tracked target the mutation is reviewable, not merely recoverable.
